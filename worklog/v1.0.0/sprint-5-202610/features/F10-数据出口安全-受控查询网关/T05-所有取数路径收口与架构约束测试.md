# T05: 所有取数路径收口与架构约束测试

**优先级**: P0
**状态**: DRAFT
**依赖**: T02

## 目标
所有取数路径都改为调用 QueryGateway，并用架构测试（ArchUnit）防止以后有人绕开。

## 技术设计
- **需要收口的路径**（以 F3/T01 的清单为准，已知的有）：`ExecuteQueryTool.java:82`（账本#17）、`SchemaLookupTool`（改为调用 QueryGateway 的专用方法 `describe(ds, objectPattern)`，只返回白名单对象的元数据）、garden 工具（F5/T04 已改为 SqlSkillTool）、NL2SQL 结果执行、模板执行、`Finance*` 中的 JDBC 执行器（`FinanceApplicationMysqlOracleJdbcQueryExecutor`、`FinanceDifferentialGridSummarySqlRowProvider` 等，在 F6 完成之前先改为调用 QueryGateway）、`FinanceApplicationMysql*JdbcConfiguration`（它们自己创建 DataSource → 改为使用 DatasourceRegistry）；
- **ArchUnit 规则**（放在 `engine-ai/src/test/java/.../architecture/DataEgressArchTest`）：
  1. `java.sql.Connection`、`javax.sql.DataSource`、`JdbcTemplate` 的使用只允许出现在 `..service.query..`、`..repository..`（JPA 访问头脑自己的库）以及 Spring 配置类中；
  2. `..service.query.internal..` 只能被 `QueryGateway` 实现类访问；
  3. `..service.copilot..`、`..service.tool..`、`..service.proof..` 不得依赖 `java.sql`；
- **头脑自己的库**（`copilot_ai` schema，JPA）不受限制，但必须与业务数据源的连接池分开（配置层面区分 bean 名称）。
