# T04: 数据源登记改造与只读账号

**优先级**: P0
**状态**: DRAFT
**依赖**: F2/T04

## 目标
数据源由管理员以 `ref` 的形式登记（Pack 只引用 ref），不再保存明文密码；每个数据源在启动或登记时自动校验"确实是只读账号"。

## 技术设计
- **现状**：copilot README 中的 `POST /api/datasources` 接收明文 `username/password`（参见 README "注册外部数据源"章节），`ToolConnectionProvider`/`ManagedToolConnectionProvider`（账本#16）按请求上下文开连接；
- **改造**：
  1. 新表 `studio_datasource`（契约见 F10 README）；原数据源表中的数据迁移过来，密码移到部署侧的 secret（环境变量 `DTS_DS_<REF>_PASSWORD`），表中只保存 `secret_ref`；原密码列清空（在迁移 changeset 中执行，执行前备份）；
  2. `POST /api/ai/datasources` 改为只接受 `{ref, dialect, jdbcUrl, username, secretRef, tenantScope, tenantColumn?}`，需要 STUDIO_ADMIN 角色；
  3. **只读自检**（登记时和启动时执行）：PG → 查询 `rolsuper`、`rolbypassrls`、`has_table_privilege(..., 'INSERT/UPDATE/DELETE')`（对声明的对象抽样检查）、`default_transaction_read_only`；MySQL → `SHOW GRANTS`；任何一项不满足就拒绝登记，已登记的数据源启动时标记为 `UNSAFE` 并禁止使用；
  4. **账号脚本**：`prs-stack/sources/deploy/sql/dts_brain_ro.sql`（prs 库）和 stack 侧 mart 库的对应脚本：`CREATE ROLE dts_brain_ro LOGIN NOBYPASSRLS; GRANT USAGE ON SCHEMA ...; GRANT SELECT ON ...; ALTER ROLE dts_brain_ro SET default_transaction_read_only = on; ALTER ROLE dts_brain_ro SET statement_timeout = '30s';`
- **Pack 绑定**：Pack manifest 中的 `datasources[].ref`（F4/T01）在激活时检查是否已登记；未登记则激活时给出警告，问数时报 `DATASOURCE_UNBOUND`。

## 验证（RED→GREEN）
- [ ] 用一个有 INSERT 权限的账号登记 → 被拒绝，错误中给出原因
- [ ] 数据库中不存在明文密码：`SELECT count(*) FROM ... WHERE password IS NOT NULL` = 0
