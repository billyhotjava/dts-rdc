# T02: 信息架构、导航与权限菜单

**原编号**: 新增（2026-09-27，ADR-013 交付方法：模板化 UI 原型先行）

**优先级**: P0 · **状态**: READY · **依赖**: T01

## 目标
所有功能点在外壳中有确定的路由、菜单位置和可见角色；401/403/租户缺失有专门页面。

## 技术设计 / UI 规格
路由表（能力标识见产品能力规划 §2）：

| 路由 | 页面 | 能力 | 默认可见角色 |
|------|------|------|--------------|
| `/workspace` | 智能体工作台 | C01/C04 | 业务用户 |
| `/data/products`、`/data/products/:id` | 数据产品（首个：在营项目） | C01 | 业务用户、数据维护者 |
| `/knowledge` | 知识检索与引用（Wiki） | C02 | 业务用户 |
| `/packs`、`/packs/:id` | Pack 管理 | C03 | Pack 维护者、平台管理员 |
| `/audit` | 审计与追溯 | C04 | 审计员、平台管理员 |
| `/evaluation` | 评估与人工接管 | C04 | 业务负责人、平台管理员 |
| `/apps/prs/*` | PRS 业务页面（远程模块） | C01 | 按 PRS 角色 |
| `/bi` | stack BI（链接/嵌入） | C01 | 按 stack 角色 |
| `/me` | 我的身份、租户与权限 | — | 全部 |

- 菜单由路由元数据 `meta.roles` 生成；角色名先用占位（`dts:business-user` 等），BL-S/T01 定稿后替换，不在组件内写死判断。
- 错误页：401（重新登录）、403（缺少角色，显示所需角色）、租户缺失（fail-closed 说明）、服务不可用（显示 traceId）。

## 验证（RED→GREEN）
- [ ] 每个角色登录后的菜单截图与上表一致
- [ ] 直接访问无权路由进入 403 页而非空白页

## Definition of Done
- [ ] 契约文件与页面同步提交；mock 模式下走查通过；截图与走查记录写入 `../../it/console/`
- [ ] 无占位证据；未接真实数据前不标“可上线”（ADR-013）

## Ready 说明

READY 仅允许基于已定 ADR-013 开展信息/交互设计；工程集成及验证依赖 T01 可用。设计产物与实现/测试分别记录，设计完成不能关闭整项 Task。

角色走查使用 T04 的六类 mock 身份；业务负责人不得遗漏。`meta.roles` 只决定展示，服务端仍独立授权。业务用户可看到自己的回答审计号，但审计页与跨用户详情只对审计员/授权管理员开放。
