# T06: 工作副本迁移与旧路径过渡

**优先级**: P1
**状态**: DRAFT
**依赖**: T02、F3/T03（copilot 已并入 studio）

## 目标
开发者和脚本从 `/opt/prod/prs/source/*` 平滑切换到 `/opt/prod/dts/dts-rdc/*`，旧路径只读保留 30 天后归档，期间不打断 prs Sprint-1。

## 技术设计
- **路径映射表**（写入 `assets/path-migration.md`）：

  | 旧路径 | 新路径 | 过渡方式 |
  |--------|--------|----------|
  | `/opt/prod/prs/source/dts-prs` | `RDC/dts-app-stack/prs-stack` | `MOVED.md` + 30 天后归档 |
  | `/opt/prod/prs/source/dts-copilot` | `RDC/dts-studio/engine` | copilot 仓库设为只读（F3/T05） |
  | `/opt/prod/prs/source/dts-stack` | `RDC/dts-stack` | 以 F0/T01 结论为准 |
  | `/opt/prod/prs/source/archived` | 保留原地（老系统参考） | 不动 |
  | `/opt/prod/prs/source/.m2` | `~/.m2` 或 RDC 统一缓存 | 由构建脚本的 `-Dmaven.repo.local` 控制 |

- **步骤**：
  1. 在所有仓库中 grep 硬编码的绝对路径：`grep -rn "/opt/prod/prs/source" --include='*.sh' --include='*.yml' --include='*.md' --include='*.json'`，逐个改为相对路径或环境变量（`DTS_HOME`）。
  2. 检查 IDE / MCP 配置：`.vscode/`、`.claude/settings*.json`、`.gitnexus/`（GitNexus 索引要在新路径重建）。
  3. 旧目录执行 `chmod -R a-w` **之前**需用户确认（会影响仍在进行的 prs Sprint-1）；建议安排在 prs Sprint-1 结束（10-16）之后。
  4. 30 天后（假设 11-20）归档：`tar czf /data/archive/prs-source-<date>.tgz`，归档前再次确认没有未推送的提交（`git log --branches --not --remotes`）。
- **错误路径**：旧路径中有未推送提交或未提交修改 → 停止归档，通知负责人。

## 验证
- [ ] 新路径下 stack / studio / prs 的构建脚本全部通过
- [ ] 旧路径 grep 结果清零（映射表中登记的例外除外）

## Definition of Done
- [ ] `assets/path-migration.md` 完成，归档记录（时间、校验和）入档
