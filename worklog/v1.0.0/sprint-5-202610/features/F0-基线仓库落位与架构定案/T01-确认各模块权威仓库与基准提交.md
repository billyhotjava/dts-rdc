# T01: 确认各模块权威仓库与基准提交

**原编号**: Sprint-5 F0/T01（2026-09-26 按月度 Sprint 整合重编号）

**优先级**: P0
**状态**: DRAFT（等待用户回答开放问题 Q1）
**依赖**: 无

## 目标
产出 `assets/source-of-truth.md`：为 dts-stack、dts-studio（含 copilot）、dts-app-stack/prs-stack、dts-infra 每个模块写明**唯一权威仓库 + 分支 + 基准 SHA**，
并处理掉"同一 URL 历史不相交"的问题（账本#1/#2/#3）。

## 技术设计
- **输入**：账本#1（RDC dts-stack → `b2a674b`）、#2（PRS/dts-stack 2877 commits，根 `7d35cfb73`，5 个未提交修改）、#3（s10-stack 3020 commits）、#4、#9。
- **输出契约**：`assets/source-of-truth.md` 表格列：
  `module | role | authoritative_remote | branch | baseline_sha | dev_path | build_path | deploy_path | owner | notes`。
- **步骤**：
  1. 只读核对远端，不 push、不 force：
     ```bash
     git ls-remote git@github.com:billyhotjava/dts-stack.git
     git ls-remote git@github.com:billyhotjava/s10-stack.git
     git ls-remote git@github.com:billyhotjava/prs-stack.git
     git ls-remote git@github.com:billyhotjava/dts-studio.git
     git ls-remote git@github.com:billyhotjava/dts-copilot.git
     ```
     记录每个远端 `refs/heads/*` 的 SHA，并判断：
     - 远端 main 是否等于 `PRS/dts-stack` 的 HEAD → 若是，说明 RDC 的 `b2a674b` 是被覆盖的旧历史，submodule 指针直接更新即可；
     - 若远端 main == `b2a674b`，说明 `PRS/dts-stack` 从未推到该 URL（可能推在别处），需决定是否把 PRS/dts-stack 推为 main（**需用户确认，属于不可逆的外部操作**）。
  2. 判定 s10-stack 与 dts-stack 的关系：取两边近 200 条提交的 subject 做 diff（`git log --format=%s`），判断是"客户交付分叉"还是"改名前后"；
     结论写入 notes（例如"s10 = 某客户 v2.2.3 交付线，只 cherry-pick 修复，不作为 DTS 平台主线"）。
  3. 对 `PRS/dts-stack` 的 5 个未提交修改（账本#2）：逐个 `git diff` 查看；由负责人决定"提交到分支 / 丢弃 / 转为 .env 覆盖"，**本 task 不擅自提交或丢弃**，只记录处置决定。
  4. 对 copilot 的 5 个未提交修改（账本#9）同样处理。
  5. 在 `source-of-truth.md` 末尾写"确认人 / 日期"。
- **错误路径**：
  - `ls-remote` 权限不足 → 记 BLOCKED，请用户执行 `! git ls-remote ...`；
  - 两份 stack 都声称是主线 → 以"最近 30 天有提交且有正式构建产物的"为准，报告给用户拍板。
