# T09: 密钥出库与轮换（copilot `.env`、prs `deploy/.env`）

**原编号**: Sprint-5 F1/T04（2026-09-26 按月度 Sprint 整合重编号）

**优先级**: P0
**状态**: READY
**依赖**: 无

## 目标
所有仓库都不再跟踪 `.env`；对曾经被跟踪、且可能是真实环境的口令完成轮换。

## 技术设计
- **输入**：账本#9（copilot `.env` 被跟踪，含 `PG_PASSWORD`、`DTS_DBT_DB_PASSWORD`，`LLM_API_KEY` 为空）；账本#7（prs `deploy/.env` 未入库，但 T06 会建库）。
- **步骤（copilot）**：
  1. 生成 `.env.example`：保留所有键，值替换为占位（`change-me` 或空），注释保留。
  2. `.gitignore` 加 `.env`；`git rm --cached .env`；提交 `chore(T09): stop tracking .env`。
  3. **判断是否需要改写历史**：确认 `PG_PASSWORD`、`DTS_DBT_DB_PASSWORD` 是否被任何非本机环境（测试/客户/生产）使用。
     - 仅本机开发默认值 → 不改写历史，在 `SECURITY.md` 记录"历史中存在开发默认口令，已失效"；
     - 在共享环境使用过 → **轮换口令**（改库用户密码 + 更新部署侧 secret），并由用户决定是否用 `git filter-repo --path .env --invert-paths` 改写历史（改写历史需要所有协作者重新 clone，**必须用户确认**）。
  4. `scripts/load-env.sh`（被 `build.sh` 引用，账本#21）：`.env` 缺失时从 `.env.example` 复制并提示，不要静默失败。
- **步骤（prs）**：T06 的 `.gitignore` 已覆盖；本 task 只核对 `.env.example` 的键是否与 `.env` 一致（`diff <(cut -d= -f1 .env) <(cut -d= -f1 .env.example)`）。
- **步骤（stack）**：检查 `PRS/dts-stack` 中是否有被跟踪的 `.env` 或 `*.p12/*.key`：`git ls-files | grep -E '\.env$|\.p12$|\.key$|\.jks$'`，结果写入证据；如有，按 copilot 同样流程处理。

## 影响范围
copilot：`.env`、`.env.example`、`.gitignore`、`scripts/load-env.sh`；stack：视扫描结果而定。

## 验证

- [ ] 删除本地 `.env` 后执行 `./build.sh`，会看到明确的提示信息
