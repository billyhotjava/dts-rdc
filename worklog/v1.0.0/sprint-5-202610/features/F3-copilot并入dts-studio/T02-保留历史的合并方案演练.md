# T02: 保留历史的合并方案演练

**优先级**: P0
**状态**: DRAFT
**依赖**: F1/T03（studio 根目录已清理）

## 目标
在 scratch 目录完整演练一次"copilot 历史重写到 `engine/` 子目录再并入 studio"，确认历史、blame、tag 都正确，并得出可重复执行的脚本。

## 技术设计
- **方案**（ADR-11）：
  ```bash
  # 1) 用 mirror clone 得到全部分支和 tag
  git clone --mirror git@github.com:billyhotjava/dts-copilot.git cp.git && git clone cp.git cp && cd cp
  # 2) 重写路径（需要 git-filter-repo）
  git filter-repo --to-subdirectory-filter engine --tag-rename '':'copilot-'
  # 3) 映射模块目录名（在一次 filter-repo 中完成）
  git filter-repo --path-rename engine/dts-copilot-ai/:engine/engine-ai/ \
                  --path-rename engine/dts-copilot-analytics/:engine/engine-analytics/ \
                  --path-rename engine/dts-copilot-webapp/:engine/webapp/ \
                  --path-rename engine/worklog/:engine/worklog-history/
  # 4) 排除不应进入 studio 的路径
  git filter-repo --invert-paths --path engine/node_modules --path engine/.dev-logs --path engine/.dev-pids \
                  --path engine/.worktrees --path engine/.env   # 与 F1/T04 的"是否改写历史"结论一致
  # 5) 并入 studio
  cd ../studio && git remote add cp ../cp && git fetch cp
  git merge --allow-unrelated-histories cp/main -m "feat(F3/T03): merge dts-copilot history into engine/"
  ```
- **演练检查项**：
  1. `git log --oneline -- engine/engine-ai | wc -l` 接近原仓库 `dts-copilot-ai` 的提交数；
  2. `git blame engine/engine-ai/.../SqlSafetyChecker.java` 显示原作者和原日期；
  3. worklog-history 体积（12 MB，账本#30）是否可以接受；如有大文件（zip，例如 `worklog/prs/v1/*.zip`），评估改用 LFS 或迁到 prs-stack；
  4. 模块目录改名后，`pom.xml` 中的 `<module>` 需要同步修改（记录到 T04）；
  5. 统计 studio 合并后的仓库体积。
- **产出**：`assets/scripts/merge-copilot.sh` 与 `assets/merge-rehearsal.md`（演练输出）。
