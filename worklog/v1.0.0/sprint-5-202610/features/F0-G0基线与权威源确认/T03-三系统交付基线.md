# T03: 三系统交付基线（同机启动、登录、问数 smoke）

**优先级**: P0
**状态**: DRAFT
**依赖**: T01

## 目标
按 `delivery-baseline` 方法，证明验收路径可用：在一台开发机上同时启动 stack + copilot + prs，
完成"登录 → 调 prs 接口 → copilot 问数"三步 smoke，把真实输出写入 `it/baseline.md`。

## 技术设计
- **输入**：stack compose（账本#24）、copilot compose（账本#21）、prs `sources/deploy/docker-compose.dev.yml`（账本#27）。
- **输出契约** `it/baseline.md` 章节：
  1. 端口冲突矩阵（三个 compose 的 host 端口全集；冲突项与调整方案，例如 prs 边缘层 38080、Keycloak 38082）；
  2. 启动顺序与命令（stack → prs → copilot），各自健康检查 URL 与真实返回；
  3. 登录：Keycloak `flower-test` realm，alice/bob 取 token 的 curl 与返回；
  4. prs：`GET /api/prs/projects`，alice 与 bob 分别返回本租户数据；
  5. copilot：API Key 方式问"当前在营项目数"，记录答案与 SQL；
  6. 资源占用（`docker stats` 快照）与已知问题。
- **步骤**：遵循各仓库自己的正式启动入口（stack 的 CLAUDE.md 禁止在开发目录构建，账本#3 → 使用构建目录或已发布镜像）；**不使用 docker cp / 容器内改代码**。
- **错误路径**：端口冲突 → 用 `.env` 覆盖 host 端口，不改 compose 默认值；Keycloak 两份实例 → 记录现状，交给 F9/T01。

## 影响范围
仅新增 `it/baseline.md`；如需 `.env` 覆盖，只放在本机，不提交。
