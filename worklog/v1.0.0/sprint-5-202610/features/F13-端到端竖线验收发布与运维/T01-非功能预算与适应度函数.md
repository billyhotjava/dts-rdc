# T01: 非功能预算与适应度函数

**优先级**: P0
**状态**: DRAFT
**依赖**: F0/T02（基线时延）

## 目标
为合并后的系统定义可以量化的质量属性，并把能自动化的检查接入 CI（fitness functions）。

## 技术设计
- **预算表**（初始值以 F0 基线为参照，实施时根据数据调整）：

  | 属性 | 指标 | 预算 | 测量方式 | 适应度函数 |
  |------|------|------|----------|------------|
  | 问数时延 | 端到端 P95（模板命中 / NL2SQL） | ≤ 基线 +10%（例如 3s / 12s） | golden set 运行器 | 夜间构建，超出预算则失败 |
  | 网关开销 | forwardAuth P95 | ≤ 5 ms | dts-auth 指标 | 压测脚本 |
  | SQL 校验 | SqlGuard P95 | ≤ 10 ms | 单测基准（JMH） | PR 门禁 |
  | Pack 生效 | 激活到生效 | ≤ 15 s | 集成测试 | PR 门禁 |
  | 审计 | outbox 积压 / 丢失率 | 积压 < 1000，丢失 0 | 指标与对账 | 夜间构建 |
  | 准确率 | golden set 通过率 | ≥ 基线 | 运行器 | 夜间构建 |
  | 安全 | 红队用例 | 100% 符合预期 | F10/T07 | PR 门禁（SQL 类） |
  | 边界 | 领域泄漏扫描 | 0（白名单除外） | F5/T07 脚本 | PR 门禁 |
  | 数据出口 | ArchUnit 规则 | 0 违规 | F10/T05 | PR 门禁 |
  | 可降级 | 头脑下线时 prs 与 stack 的主功能 | 100% 可用 | 演练 | 发布前 |
