## 目标
`SemanticPackService`（账本#12，`:21` 从 classpath 读取）改为通过 `PackAssetResolver` 获取 `ontology` 资产；
`OntologyService`、`BusinessObjectCatalogService`、`IntentRouterService` 等下游**零改动或只做最小改动**。

## 技术设计
- **改造点**：
  1. 抽出接口 `SemanticPackSource { List<SemanticPack> loadAll(); long generation(); }`，提供两个实现：
     - `RegistrySemanticPackSource`（默认）：读取所有 ACTIVE pack 中 kind=`ontology` 的资产，反序列化为现有的 `SemanticPackService.SemanticPack` record；
     - `ClasspathSemanticPackSource`（回退）：保留原有逻辑，仅在 `dts.studio.pack.fallback-classpath=true` 时启用（过渡期默认 true，T14 验收后改为 false，BL-E 之后删除）。
  2. `SemanticPackService` 的缓存：以 `generation` 作为版本号，generation 变化时重建索引（不重启进程）；
  3. **多 pack 同 domain 冲突**：两个 ACTIVE pack 声明同一个 `domain` 时，安装阶段就拒绝（T03 的校验中增加跨 pack 检查），运行时不做合并；
  4. 答案溯源：`CopilotChatContract` 的 `sourceRefs[]` 增加 `{type:"pack", name, version}`（与 BL-A 的 UI 契约保持一致）。
- **不改动**：`OntologyService.OntologyModel` 的内部结构。

## 2026-09-30：答案版本溯源实现

已接通语义/规则缓存、提示词直读、查询模板所有权与 Agent 执行记录。普通回答、SSE `done`、历史消息读取均包含同一份结构化 `packRefs[{type,name,version}]`，原始证据写入 `trace.packRefs`。

接口核对发现：既有 REST `sourceRefs` 实际为字符串，SSE 为字符串数组。为保持迁入 API 的兼容性，本次先增加 `packRefs`；原设计的统一 `sourceRefs[]` 由 T17 → BL-C/T02 显式适配，不能直接替换旧字段或反向修改已冻结的 Console 契约。

来源取自实际读取的资产及缓存所属版本；模型生成期间发生激活不会把旧回答重标成新版本。如果一次执行确实读取过两个版本，就记录两个版本；不承诺整次执行固定一个 generation。查询模板通过所属版本 ID 追溯，手工与历史模板不虚构 Pack 版本。字段代表被读取/查询的能力包依赖，不证明每个资产都贡献了最终答案。
