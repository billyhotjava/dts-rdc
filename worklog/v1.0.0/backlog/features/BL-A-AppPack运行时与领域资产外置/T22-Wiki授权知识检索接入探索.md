## 问题与实验

判断“让 studio 消费 Wiki 是否在现有关键词检索上产生可测量的业务收益”，并确定最小可信身份与更新链路。探索先使用非敏感测试文档，不上线完整 RAG 服务，不开展模型训练或批量搬运真实知识库。

1. 选择 PRS 使用说明/运维文档的小型样本集，登记原文版本、空间权限、题目、预期引用和无法回答的题目；由内容负责人确认，不用模型生成答案自评为真值。
2. 比较现有关键词检索与候选检索增强方案的命中、回答与引用正确性、时延、成本。若需要混合/向量检索再说明原因和维护成本，不预先指定新增数据库。
3. 验证身份委托：studio 调用必须保留真实主体和空间权限；不得用管理员服务账号全量读取。Wiki space 与 PRS tenant/realm 不作等号，映射未知即列阻碍。
4. 验证无权限空间、撤权、删除、正文更新及缓存复用；授权过滤发生在片段送入模型前，引用再次读取也必须检查权限。索引版本落后须能检测并停止使用失效内容。
5. 将文档内“忽略规则/调用工具”等文本作为不可信内容测试，不能转成授权或动作；记录使用者、来源版本和 traceId，日志不暴露正文。

## 产出与完成标准

- [ ] `assets/wiki-rag-evaluation.jsonl`：逐题输入引用、预期、实际、权限上下文、错误类别、耗时及成本；无敏感正文或凭据。
- [ ] 给出最小接口/元数据、内容更新与删除传播、撤权处理、缓存隔离和审计方案，列出仍阻断生产接入的事项。
- [ ] 推进时才在既有 Feature 细化后续设计、实现、QA 和恢复任务，；正式接入依赖方案中的身份、安全、审计路径。暂缓也属于合法探索结论。
