# T14: 其余用例的声明式迁移

**原编号**: Sprint-5 F6/T04（2026-09-26 按月度 Sprint 整合重编号）

**优先级**: P1
**状态**: DRAFT
**依赖**: T13

## 目标
按 T11 表格，把其余的 Finance 证明能力逐组迁到 ProofEngine + Pack 资产，每迁移一组都做新旧并行比对。

## 技术设计
- **迁移顺序**（从简单到复杂）：
  1. invariants（`FinanceInvariant*`）→ `invariant` check；
  2. voucher/subject tieout（`FinanceVoucherSubjectTieout*`、`VoucherLedgerTieout*`）→ `tieout`；
  3. differential grid（`FinanceDifferentialGrid*`，包括 SQL row provider）→ 参数化 cases（grid 展开为多个 case）；
  4. detail reconciliation（harness + HTTP payload + JSON source client）→ `http-json` source；
  5. application MySQL authority/oracle proof（`FinanceApplicationMysql*`，含 JDBC 配置）→ `sql` source + 数据源 `prs-app-legacy`（在 QueryGateway 中注册只读数据源，连接信息放在部署配置中）；
  6. scorecard / snapshot / scheduled publisher / weak-path candidates → `ScorecardPublisher` + `schedule`；
  7. signoff baseline → 作为 `snapshot` source 的基线 run（标记 `baseline=true`）。
- 每组迁移：转写资产 → 新旧并行比对 → 报告 → 在 `domain-leak-allowlist.txt` 中移除对应条目。
- **调度**：旧的 `*ScheduledPublisherService` 使用 `@Scheduled`；新引擎统一由 `ProofScheduler` 执行，并使用 PG advisory lock 保证多副本只执行一次（符合 R-011 k8s-ready 中"定时任务支持多副本"的要求）。
