## 目标与边界

以“在营项目”为唯一新增交付样例：项目经理通过原业务/API 路径与 studio 问数，使用同一已发布口径，得到权限范围内一致的明细集合与计数，并能识别来源、版本和更新时间。

复用 stack 资产目录、指标发布/查询、质量与血缘落点，以及 PRS 原业务入口。若缺少元数据，先列复用映射与最小扩展，不建设独立数据产品注册库或新菜单；不依赖全部 BI/Finance 迁移。

## 实施与契约

1. 明确资产/指标稳定引用、负责人、明细粒度、过滤条件、快照时点、来源及质量规则的现有字段映射；具体类型、空值与状态在开发前补齐。PRS 交易事实归 PRS，指标定义归 ADR-007 确定的 stack 控制面。
2. 在确认口径后提供同源明细与计数。比较上下文至少含用户、租户、权限范围、数据快照、指标版本；需要的字段授权同样生效。
3. 复用 `indicatorRef`、`sourceRefs`、`accuracyEvidence` 与 traceId，补齐来源版本、数据更新时间/质量结果的展示映射；如需协议扩展由 BL-A/T17 统一维护。
4. 缺租户/未授权显式拒绝；合法空集合返回 0 且保留来源。未发布或撤回的指标不可用缓存继续供数；过期、质量失败和上游不可用按 F0/T14 方案明确降级或拒绝。
5. 用现有 API/页面完成一次人工路径，再用 AI 执行同批任务；为 BL-E/T01 阶段 A 提交接口版本、数据样本、预期集合和缺陷清单。

## 验证与完成条件

- [ ] 开发前字段/类型/发布状态、复用点、数据规模与新鲜度阈值明确；缺口映射到实施工作。
- [ ] 单元/契约验证：正常、空集合、删除记录排除、口径变更、过期、质量失败、未发布、撤回、缺身份、跨租户；期望由 F0/T04 确认。
- [ ] 两租户的可见 ID 集合分别精确相等；种子计数相同不视为隔离失败，也不能作为隔离成功的唯一证据。
- [ ] 同一快照下业务/API 与 AI 明细和计数一致；记录版本、时延、失败与成本，禁止硬编码示例数值。
- [ ] 源变更/删除后的结果更新，以及权限变化后缓存不泄漏的集成验证通过。
- [ ] 开发验证与 QA/业务验收分栏记录，证据写入拉入后 Sprint 的 `it/IT-data-product-prs.md`；BL-E/T01 负责跨模块业务验收。
