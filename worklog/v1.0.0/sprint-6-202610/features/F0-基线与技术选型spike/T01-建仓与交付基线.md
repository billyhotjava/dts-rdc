# T01: 建仓与交付基线

**优先级**: P0 · **状态**: DRAFT · **依赖**: 用户在 GitHub 新建空仓库 `billyhotjava/dts-wiki`

## 目标
一个"什么业务都没有"的 dts-wiki 从本机构建出镜像，传到 .50 用 compose 启动，浏览器经阿里云边缘打开并完成 Keycloak 登录。

## 技术设计
- 仓库结构：
  ```
  dts-wiki/
    backend/    Spring Boot 4.1.x（Maven wrapper），包名 com.yuzhi.dts.wiki
    frontend/   React 19 + TS + Vite + antd，pnpm
    deploy/     compose.yml、nginx.conf（静态前端 + /api 反代）、.env.example、aliyun/*.conf
    docs/       README、架构、运维
  ```
- 加入 dts-rdc：`git submodule add git@github.com:billyhotjava/dts-wiki.git dts-wiki`。
- 镜像：`dts-wiki-app`（eclipse-temurin:25-jre + fat jar，非 root 运行）、`dts-wiki-web`（nginx:1.28-alpine + 前端产物）；
  由于账本 #7，镜像在本机构建，经 `docker save | ssh docker load` 传到 .50。
- .50 目录 `/data/dts-wiki-v2/`（与现网 `/data/dts-wiki` 并行，互不影响）；端口 18091（web），app 不暴露。
- 临时域名：`wiki2.yuzhicloud.com`（需用户加 DNS），证书 certbot，阿里云 vhost 仿 `deploy/wiki/aliyun`。
- 健康检查：`/actuator/health/liveness`、`/actuator/health/readiness`（R-011 k8s-ready：探针分离、优雅停机、stdout JSON 日志）。

## 验证
- [ ] `./mvnw -q verify` 与 `pnpm build` 在本机通过
- [ ] .50 上 `docker compose ps` 两个服务 healthy
- [ ] 浏览器打开 `https://wiki2.yuzhicloud.com` 看到"Hello + 当前登录用户名"（登录链路见 F2，本 task 可先用占位页）
