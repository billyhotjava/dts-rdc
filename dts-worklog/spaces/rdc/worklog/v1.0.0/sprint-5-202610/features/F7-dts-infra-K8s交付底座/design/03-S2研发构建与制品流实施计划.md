### D-S2-4（待用户决定）：日志采集与 chart-spec 的 hostPath 规则

VictoriaLogs（D14）负责存储，采集需要节点级 DaemonSet 读取 `/var/log/pods`。这和 CHART006（禁止 hostPath）冲突；而且日志文件归 root 所有，也与 CHART005（restricted）冲突。

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（建议）** | 新增受限例外规则：只有显式声明为节点代理的 DaemonSet（注解 `infra.dts.yuzhicloud.com/node-agent: <理由>`）可以**只读**挂载 `/var/log` 下的路径；可以 `runAsUser: 0`，但仍需 `readOnlyRootFilesystem`、`drop ALL` 并只加 `DAC_READ_SEARCH`、禁止 privileged/hostNetwork；chartcheck 机检，Kyverno（T23）在集群内执行同一策略。采集器用 Fluent Bit（Apache-2.0，CNCF 毕业项目）写入 VictoriaLogs | 例外有边界、可审计；符合行业做法 |
| B | 不做节点采集，各模块直接通过 OTLP 推送日志 | 第三方组件（CNPG、Keycloak、cert-manager）做不到 |
| C | v1 只用 `kubectl logs` | 不满足 D14 和运维需求 |

选 A 之后的工作：CHART016 规则及测试、`dts-victorialogs`（单实例，存储走 `global.storageClass`）、`dts-log-agent`（Fluent Bit DaemonSet），最后在 dts-local 上做端到端验证。
