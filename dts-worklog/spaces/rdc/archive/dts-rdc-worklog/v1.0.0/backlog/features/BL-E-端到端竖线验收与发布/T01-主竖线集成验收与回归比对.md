## 阶段 A：首次业务联调与价值基线

- 准备：固定真实受测 SHA/镜像 digest、租户/用户/角色、数据快照、指标/Pack 版本和独立确认的 oracle；仅使用授权的非敏感测试数据。
- 正向：原 PRS 页面/API 获取在营项目集合与计数 → studio 同题问数 → 核对同口径结果、来源、版本、新鲜度/质量与 traceId → 查验 asked/query/answered 审计事件经 outbox、Kafka 到 append-only 存储。
- 负向：缺身份/租户、跨租户、指标未发布/撤回、过期缓存与上游异常必须按确认规则拒绝或降级；同计数的两个租户仍逐一验证可见 ID。拦截行为也需留审计证据。
- 价值：用 F0/T18 同批任务测量人工/API 与 AI 时间、成功率、纠正次数、模型调用/token/可获得费用；保留失败重试，不宣称未经测量的改善比例。
- 验证级别：开发集成、QA 和业务确认分别记录，业务验收人缺席则保留待验收；首个场景失败须有缺陷及下一步，不以演示录屏代替真实断言。
- 证据：当期 Sprint `it/IT-10A-prs-first-integration.md`；部分通过只记录阶段进度，不把 T01 或依赖任务的全范围标 DONE。

## 阶段 B：完整集成与发布前验证
- **环境**：统一网关 + dts-auth + Keycloak + studio（engine-ai、Console、console-bff）+ stack（platform、analytics、kafka、pg）+ prs（platform、project）；镜像均来自正式构建流程，记录每个镜像的 digest 与 commit SHA（遵循 stack CLAUDE.md 的一致性要求，账本#3）；
- **自动化**：Playwright 脚本 `e2e/dts-v1-slice.spec.ts`（放在 RDC 的 `tests/e2e/`，跨模块验收属于总纲仓库），覆盖走查 1–6，每步截图；
- **逐层证据**（写入 `it/IT-10-e2e-slice.md`）：
  1. Keycloak token（脱敏后的 payload）；2. 网关访问日志中该请求的路由；3. engine-ai 日志中的 traceId、路由结果、pack 版本；
  4. SqlGuard 结果与 SQL hash；5. 数据库中 `app.tenant_id` 生效的证据（`pg_stat_activity` 抽样或 RLS 测试）；6. Kafka 中的事件（通过 kafka-ui 截图或 kcat 输出）；7. stack 审计存储的查询结果；
- **回归**：golden set 全量运行，按 F0/T02 的相同上下文做语义比对；纯搬迁需等价，已接受的租户/安全/口径变化对照新 oracle，SQL hash 单列诊断且安全断言零容差；红队用例全量运行；
- **可降级演练**：先通过 BL-D/T05 关闭 AI，验证 Console/BFF 状态与人工路径、PRS `/api/prs/projects` 和 stack 分析中心仍可用；另模拟 engine-ai 故障（不停止 Console/BFF），证明故障降级，分别留证。
- **质量与价值**：重跑 BL-D/T17 业务一致性，执行 F0/T18 中本期实现对应的检查并接入 CI；预算设计、运行达标和业务收益分别留证。Wiki RAG 仅在另行细化并拉入发布范围时验收，不以 T22 探索结果代替。
