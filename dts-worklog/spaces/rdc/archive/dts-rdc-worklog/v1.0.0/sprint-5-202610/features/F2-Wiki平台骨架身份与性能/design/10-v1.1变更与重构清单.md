## 3. 后端改造

### 3.1 B1 内容分析：`ContentService`（新增 `service/wiki/content/`）
```
content/
  ContentService.java          analyze(md, mode) → ContentAnalysis
  FrontmatterParser.java       split + YAML 解析（SnakeYAML，Spring Boot 已带）
  ContentSchemaRegistry.java   启动加载 classpath:content-schemas/*.schema.json
  MarkdownText.java            正文 → 纯文本、标题列表（commonmark-java + gfm tables 扩展）
  ContentAnalysis.java         record: frontmatter(Map), body(String), docType, docId, status, title,
                                        owner, tags, depends, related, sprint, feature, priority,
                                        valid(boolean), errors(List<FieldError>), plainText, headings
```
- **frontmatter 切分规则**（前后端必须一致）：文件以 `---\n`（或 `---\r\n`）开头，到下一行恰为 `---` 为止；其余为正文。无匹配 → 无 frontmatter。
- YAML 解析失败 → `valid=false`，错误 `{path:"$", message:"YAML 语法错误: …"}`。
- `type` 缺省或未知 → `page`；已知类型 → 用 `com.networknt:json-schema-validator`（Apache-2.0，取 R-012 规则下最新稳定版）按 2020-12 校验，错误映射为 `{path, message}`（中文 message 由我们按关键字翻译：required/enum/pattern/type）。
- `title` 取值顺序：frontmatter.title → 正文首个 `# ` 标题 → 页面标题。
- 重复 `id`：同空间已有另一页面 `page_meta.doc_id` 相同 → 追加错误 `{path:"id", message:"与 <路径> 重复"}`，`valid=false`。
- `mode = STRICT`（网页/Agent 保存）：`valid=false` → 抛 `FrontmatterInvalidException` → 422 `{errorKey:"FRONTMATTER_INVALID", errors:[…]}`；
  `mode = LENIENT`（git 入站、导入）：照常入库，记录 `valid=false` 与 errors。
- 接入点：`PageService.addVersion(...)` 前调用 `analyze`；成功后在同一事务内 `PageMetaDao.upsert`、`SearchIndexService.upsert`（取 `plainText`、标题 + tags）。
- 测试：`ContentServiceTest` 覆盖 09 §3.2 每种类型的合法/非法样例（每类 ≥ 3 非法）、YAML 错误、无 frontmatter、CRLF、重复 id、title 推导。

## 4. 前端改造

### 4.1 F1 最小差异保存（`frontend/src/features/edit/minimalDiff.ts`，纯函数 + Vitest）
目的：编辑器（remark 序列化）会把整篇文档重排（表格对齐、转义、空行），直接保存会让 git diff 覆盖全文。算法只替换**语义上被改动的顶层块**，其余块保留原文字节。

```
minimalDiff(originalBody: string, editedBody: string): string
  A = parse(originalBody)        // unified + remark-parse + remark-gfm + remark-directive + remark-math，保留 position
  B = parse(editedBody)          // editedBody = crepe.getMarkdown()（仅正文，不含 frontmatter）
  fa = A.children.map(fingerprint); fb = B.children.map(fingerprint)
  ops = lcs(fa, fb)              // Myers/LCS 对齐顶层块序列
  out = []
  for op in ops:
    equal(i, j)   → push 原文切片 original[A[i].start.offset .. A[i].end.offset]
    insert(j)     → push 新文切片 edited[B[j].start.offset .. B[j].end.offset]
    delete(i)     → 跳过
  块之间的分隔：两个连续"保留块"之间使用原文中两块之间的原始空白；其余情况用 "\n\n"
  文首空白与文末换行：沿用原文（原文无末尾换行则不加）
  return out.join('')

fingerprint(node) = sha1(JSON.stringify(stripPositions(normalize(node))))
normalize：去掉 position/data；text 值 trim 并折叠空白；表格单元格值 trim；代码块保留原样（语言 + 内容）
```
- 替换块内部仍是编辑器的规范格式（可接受：只影响用户改过的块）。
- 当 `minimalDiff(original, edited) === original` 时视为未修改，不保存。
- 在 `PageEditorPage` 保存前调用：`content = frontmatter + minimalDiff(originalBody, editorBody)`。
- **单元测试（必须）**：用 `assets/wiki/editor-spike.md` 的 20 个样本（从 `/tmp/opencode/editor-spike/harness/samples/` 拷入 `frontend/tests/fixtures/md/`）：
  1. 不修改：输出 === 原文（20/20）；
  2. 改段落中一个字：`diff` 行数 = 1；
  3. 在大表格中改一个单元格：只该表格块变化，其他块字节不变；
  4. 在列表末尾加一项、删除一个标题、调整两个段落顺序：只涉及的块变化；
  5. 幂等：`minimalDiff(x, x) === x`。

## 7. W12 frontmatter 迁移脚本规则

- 范围：当前 Sprint-5 及以后月度 Sprint、`backlog/`；归档、3 月未执行 Sprint、历史证据正文不批量重写。W12 由 F4/T05 承接，安排在切换前。
- 类型：月度 Sprint 根 README → sprint；`features/F<n>-*/README.md`、`backlog/features/BL-<X>-*/README.md` → feature；其 T<nn> 文件 → task；递归 `it/**/*.md` → evidence（索引 README 按 page）；design/assets → page。
- ID：Sprint `sprint-N`；Feature `S<N>/F<n>` 或 `BL-X`；Task `S<N>/F<n>/T<nn>` 或 `BL-X/T<nn>`；嵌套证据 ID 纳入相对子路径，避免根 IT-03 与 wiki/IT-03 相撞。迁入月度目录时保留旧 ID 到 aliases，按已登记对照迁移引用，不根据当月 F0 猜测旧 Sprint-5 F0。
- 字段提取支持 ASCII/全角冒号、一行多个 ` · ` 字段及状态后的日期/说明；状态值单独提取，附带说明和原行完整保留。禁止前 20 行截断后假定已覆盖，限定为标题后的元数据区域，遇到正文标题停止。
- depends 按最长完整 ID 优先解析：`S5/F0/T07`、`Sprint-5 F0/T07`、`BL-S/T08`、`F0/T07`、本 Feature `T07`。支持 `T01–T03`、`F0/T12～F0/T16` 和 `BL-S/T01～T11` 等同作用域闭区间，逐项核对目标存在；不能把 BL-S/T08 截成当前 Feature 的 T08。
- 整 Feature 依赖保留完整 Feature ID，不凭空改成某个 Task；跨 Feature 范围、阶段 A/B、部分条款、自然语言附加条件等不能完全表达为 ID 集合时，将整段写入 `depends_note` 并保留原依赖行，标为人工核对，不能声称自动依赖图完整。
- **迁移保真**：本轮工具默认保留全部正文元数据行，不执行抽取成功即删行。未知字段与解释不丢弃；已有 frontmatter 与正文冲突则报告并跳过该文件，不选择性覆盖。同步库 schema 由 T05 扩展为支持 BL ID、aliases 与 depends_note，回归 F3/T13 原有校验。
- dry-run 报告包含目标类型/ID、字段及原文映射、解析到的边、未解析条件、重复/悬空 ID、冲突文件。需求方确认后才 apply；不在本次文档 review 运行迁移。
- 执行前后比较文件集合、正文哈希、完整 ID/aliases、状态、依赖边集合与 depends_note；幂等二次运行无变化。Schema 校验通过不能替代语义守恒。
- 必测样本：S5/F0、BL-A、BL-S/T08、范围、多前缀/省略前缀、整 Feature、阶段 T10-A/T10-B、同行多个字段、全角冒号、元数据超过 20 行、未知说明、嵌套 it/wiki、重复 ID、已有 frontmatter 冲突。
- 模板更新属于本任务明确列出的产出；只修改仓库内 sprint-workflow 模板，不改个人全局技能或 memory。
