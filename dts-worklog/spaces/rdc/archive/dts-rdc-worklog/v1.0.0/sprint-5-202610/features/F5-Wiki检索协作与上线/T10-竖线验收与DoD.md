## 阶段 A：切换前完整验收

在 18091 测试实例执行下列脚本与 design/07 本期功能、权限、同步竞争用例。证据写入 `it/wiki/IT-05-cutover.md` 的 pre-cutover 节（Sprint 根相对路径），含版本/数据/用例/缺陷。阻断项通过后才向 T09 交付切换结论，不等待生产切换后首次完整验收。

1. 梅卫锋式账号（产品-PRS + 研发部）登录，只看到 PRS 与练习区空间；
2. 打开 PRS worklog 某页 → 编辑 → 保存 → 60 s 内 prs-stack 出现作者为该用户的提交（`git log -1`）；
3. 在本机修改 prs-stack 另一 worklog 文件并 push → 60 s 内 wiki 出现新版本，历史显示"来自 git"；
4. 同时两边改同一页同一行 → 冲突徽标 → 三方合并 → 合并结果写回 git；
5. 改名、移动、删除各一次 → git 中为 rename/delete；
6. 搜索中文词、查看历史对比、恢复旧版本、发表评论并 @同事 → 对方收到站内通知；
7. 旧书签 `/p/dts/worklog/...` 跳转到对应新页面。

8. Agent 只读接口与 MCP 的真实主体权限、撤权/删除、写入冲突、署名和限流符合 F3/T15/T16。
9. W12 迁移的 ID、依赖与状态守恒；未确认迁移不得跳过并标通过。

## 阶段 B：切换后冒烟与完成

T09 完成后以同一发布版本验证正式域名登录/登出、空间隔离、阅读/保存、两个同步方向、旧链接与关键 MCP 调用，并核对出站积压。失败触发 T09 回退。

顺序为 `T10-A → T09 → T10-B`，不是整项 Task 互相等待。两个阶段及回退证据齐全、缺陷处置明确后才关闭 T10 和 Wiki G4。

10. 编辑器验收核对 F3/T04、T06～T09 及 W5c 的未完成清单：双会话冲突、草稿/编辑提示、实际粘贴、方言与模板；未实现项需修复并补证，阶段 DONE 标记不豁免本期验收。
