## 3. 同步场景（集成测试，本地 bare 仓库模拟 GitHub）
每个场景断言：PG 页面/版本/状态、工作副本与远端的 `git log`（作者、提交数、文件内容）。

1. 首次导入：文件数 = 页面数；README → FOLDER 正文；图片 → 附件；历史版本数 ≤ 20
2. wiki 新建 / 编辑 / 改名 / 移动目录 / 删除 / 恢复 / 上传图片 → 远端各一个提交，作者正确，改名为 rename
3. git 新增 / 修改 / 删除 / 改名 / 目录改名 / README 修改 → wiki 对应变化，页面 id 不变
4. 两边改不同行 → 自动合并，MERGE 版本，推送成功
5. 两边改同一行 → CONFLICT；普通保存 409；三方合并后推送成功，冲突关闭
6. git 删除、wiki 修改 → 冲突；"保留 wiki 版本"后文件恢复
7. 推送被拒（远端并发提交）→ 下一周期重放成功，无重复提交
8. 远端不可达 → status=OFFLINE，恢复后自动追平；outbox 不丢
9. 同一周期重复执行（幂等）；中文路径与文件名；超大文件被跳过并告警

## 5. 验收脚本（上线门禁，证据放 dts-rdc `worklog/v1.0.0/sprint-5-202610/it/`）
1. 以"产品-PRS + 研发部"成员登录（验收期 `http://10.20.0.50:18091`），只看到 PRS 与练习区空间；
2. 打开 PRS 工作日志某页 → 编辑 → 保存；60 s 内 prs-stack 远端出现作者为该用户的提交；
3. 在开发机修改 prs-stack 另一 worklog 文件并 push；60 s 内 wiki 出现新版本，历史显示"来自 git"；
4. 两边同时改同一页同一行 → 冲突徽标 → 三方合并 → 合并结果出现在远端；
5. 改名、移动、删除各一次 → 远端为 rename / rename / delete 提交；回收站恢复 → 远端文件恢复；
6. 中文检索命中；历史对比与恢复；评论并 @同事 → 对方站内通知；
7. 旧书签 `/p/dts/worklog/v1.0.0/sprint-5-202610/` 跳转到对应新页面；
8. 恢复演练：备份还原到临时库，页面数、版本数一致。
