# 05 前端设计（React + antd）

## 1. 技术选型与工程结构
| 方面 | 选择 |
|------|------|
| 框架 | React 19 + TypeScript（`strict`，不允许 `allowJs`） |
| 组件库 | **antd 6**（`@ant-design/icons` 6），`ConfigProvider` 统一主题与 `zh_CN` 语言包 |
| 路由 | React Router 8（数据路由 `createBrowserRouter`） |
| 服务端状态 | TanStack Query 5（缓存、重试、乐观更新）；**不引入 Redux**，少量全局 UI 状态用 React Context |
| HTTP | axios 实例：`withCredentials`、`X-XSRF-TOKEN`（JHipster 默认启用 CSRF，读 `XSRF-TOKEN` Cookie）、401 时整页跳转登录 |
| 接口类型 | 由后端 OpenAPI 生成：`openapi-typescript` 读取 `/v3/api-docs`（后端 `api-docs` profile），产物 `src/api/schema.d.ts`，不手写重复类型 |
| 国际化 | react-i18next，默认 `zh-CN`，另有 `en`；文案文件 `src/locales/{zh-CN,en}/*.json` |
| 构建 | Vite + pnpm；单元测试 Vitest + Testing Library；E2E Playwright |
| 编辑器 | **Milkdown Crepe**（spike 已定），封装为 `MarkdownEditor`；自定义节点 `callout`、`raw_block`；源码模式 CodeMirror 6（`@codemirror/lang-markdown`、`lang-yaml`） |
| 最小差异 | unified + remark-parse + remark-gfm + remark-directive + remark-math（与编辑器同版本），`minimalDiff.ts`（§4.3） |
| 属性 | `yaml`（eemeli，Document API 保留注释与顺序）+ `ajv`（2020-12）按服务端 schema 校验 |
| 渲染 | markdown-it + footnote / container / anchor(github-slugger) / task-lists / GitHub alerts；mermaid、Shiki、KaTeX 均动态 `import()`（§6） |
| 性能门禁 | `scripts/check-bundle-size.mjs`（§8.1） |

## 3. 布局（antd Layout，Confluence 式）

```
┌ Header ──────────────────────────────────────────────────────────────────────────┐
│ DTS Wiki │ <Select 空间: PRS 花卉租赁> │ <Input.Search 全局搜索> │ <Button ＋新建> │ <Badge 🔔3> │ <Dropdown 谢志民> │
├ Sider (可折叠, 宽 300) ──┬ Content ─────────────────────────────────────────────────┤
│ PRS 花卉租赁             │ <Breadcrumb 首页 / 工作日志 / v1.0.0 / sprint-1-202609>   │
│ <Tree>                    │ <Typography.Title>Sprint-1：可运行基线</Title>  [编辑] [⋯] │
│  ▸ 产品文档              │ <Space> 谢志民 · 2 小时前 · 版本 7 · <Tag git> prs-stack@abc1234 │
│  ▾ 工作日志              │ <Alert type=error 同步冲突：此页在 git 中也被修改 [去合并]>  │
│    ▾ v1.0.0              │ <Tabs 正文 | 附件(3) | 历史>                                  │
│      • sprint-1-202609   │  正文（MarkdownView）+ 右侧 <Anchor> 目录                     │
│      • sprint-queue      │ <Divider> 评论（CommentSection）                               │
│ ─────────                │                                                                │
│ 回收站 · 空间设置         │                                                                │
└──────────────────────────┴────────────────────────────────────────────────────────────────┘
```

- **页面树**：antd `Tree`（`virtual`，`height` 撑满侧栏；`draggable` 拖拽排序与改父节点，`onDrop` 前校验不可放入自身子孙）；节点标题右侧悬停显示 `Dropdown` 菜单（新建子页、改名、移动到…、复制、删除）；当前页 `selectedKeys` 高亮并展开祖先；`SyncBadge` 显示 同步中 / 冲突。
- **四态**：所有数据区块用 `AsyncState`：加载用 `Skeleton`，空用 `Empty`（带引导按钮），错误用 `Result status="error"` + 重试。
- **操作反馈**：保存、移动、删除用 `message`；删除、覆盖他人修改、恢复版本用 `Modal.confirm`（写明对 git 的影响，如"将在仓库中删除该文件"）。

## 4. 编辑（PageEditorPage）
- `MarkdownEditor` 封装（对外只暴露 Markdown 字符串）：`value`、`onChange`、`onUploadImage(file) => Promise<string>`（返回插入的 Markdown）、`readOnly`。
  必须满足：打开后不修改则不触发 `onChange`、不发保存请求；YAML frontmatter 不进入编辑区（由属性表单编辑）。编辑器自身的序列化会重排格式（spike 结论：无法字节不变），因此**保存内容一律经 §4.3 最小差异处理**，保证未改动的块字节不变。
- 页面顶部：标题 `Input`、保存按钮（Ctrl/⌘+S）、"保存说明"（可选，写入版本 message 与 git 提交信息）、取消。
- 409 版本冲突 → `VersionConflictModal`：[查看差异]（打开 VersionDiff 抽屉）[加载最新版本] [仍用我的版本覆盖]（二次确认）。
- 409 同步冲突 → 引导到 `/conflicts/:id`。
- 草稿：内容变化后每 5 s `PUT /draft`；打开时若服务端草稿比当前版本新 → `Alert` "发现 X 时间的未保存草稿 [恢复] [丢弃]"。
- 协作提示：每 30 s `POST /editing`；他人在编辑时 `Alert type=warning` 显示姓名（`Avatar.Group`）。
- 离开有未保存内容 → `useBlocker` + `beforeunload` 提示。
- 图片：粘贴/拖拽 → `POST /attachments` → 插入返回的 `markdown`；编辑器内预览 `./assets/x.png` 走 `/api/wiki/pages/{id}/raw/assets/x.png`。

### 4.1 编辑区组成（v1.1）
```
┌ 标题 Input ─────────────────────────────── [所见即所得 | 源码] [保存 Ctrl+S] [取消] ┐
│ ▸ 属性（PropertiesForm，可折叠；无 frontmatter 的普通页默认折叠并显示"添加属性"）      │
│ 正文编辑区（Milkdown：/ 菜单、块拖拽手柄、浮动工具栏；或 CodeMirror 源码模式）          │
│ 保存说明 Input（可选，写入版本 message 与 git 提交信息）                                │
└────────────────────────────────────────────────────────────────────────────────────┘
```
- 属性表单与 YAML 源码切换、类型推断、ajv 预校验、422 字段映射：见 10 §4.3。
- 方言支持（提示框节点、源码块、archify 只读卡片、Mermaid 预览、@提及）：见 10 §4.2；`/` 菜单新增：提示框 ×5、Mermaid、archify 引用、折叠块（插入源码块模板）。

### 4.2 源码模式
CodeMirror 6 直接编辑**完整原文**（含 frontmatter），保存时原样提交、不经最小差异处理。适合开发者、批量调整与 Agent 协作场景。切回所见即所得时用源码重建编辑器（未保存的修改保留）。

### 4.3 最小差异保存（关键，D11）
所见即所得模式保存前：`content = frontmatterText + minimalDiff(originalBody, crepe.getMarkdown())`。
算法（按顶层块 LCS 对齐，未改动块保留原文字节）、边界规则与必须通过的 20 样本测试，见 **10 §4.1**。
结果与原文完全相同时视为未修改，不发请求。

## 5. 历史、对比与冲突合并
- HistoryPage：`Timeline` 列出版本（作者头像、时间、来源 `Tag`：网页 / git（提交号可点击跳 GitHub）/ 合并 / 恢复、说明）；勾选两个版本 → 对比；每个版本 [查看] [恢复到此版本]。
- VersionDiff：jsdiff 行级对比，`Segmented` 切换"并排 / 统一 / 渲染对比"。
- ConflictMergePage：上方三栏只读（基线 / wiki 版 / git 版，差异高亮），下方结果编辑区（CodeMirror 6，预填 `git merge-file` 结果，冲突块高亮），按钮 [采用 wiki 版] [采用 git 版] [保存合并结果]。

## 6. Markdown 渲染（MarkdownView）
完整实现要求见 **10 §4.4**，要点：
- markdown-it（`html:false`、`breaks:true`）+ DTS-MD v1 扩展（09 §2.2）：提示框、脚注、容器指令（details/columns）、任务列表、标题锚点（github-slugger）。
- 代码块钩子：`mermaid` → MermaidBlock（懒加载）；`archify` → ArchifyFrame（沙箱 iframe，工具栏，PNG 退化，09 §4.2）；其他 → Shiki 高亮（懒加载，失败退化纯文本）。
- frontmatter 不进正文，由 PropertiesPanel 展示。
- 相对 `.md` 链接经 `resolve-batch` 一次解析为站内路由；`./assets/*`、`./diagrams/*` 指向 raw 接口；外链新窗口。
- 长文档：顶层块 `content-visibility: auto`；图片懒加载；右侧 Anchor 目录。
- 目录页（FOLDER）无 README 正文时显示子页面卡片（ChildPagesGrid：标题、类型图标、状态、更新时间），不显示"无正文"占位。

## 7. 管理后台（antd）
- SpacesAdminPage：`Table`（名称、标识、仓库、同步根、页面数、状态）+ `Drawer` 表单新建/编辑空间（`Form` 校验 slug 规则 `^[a-z][a-z0-9-]{1,30}$`）。
- SyncAdminPage：每个空间一张 `Card`：同步状态 `Badge`、最后同步时间、`lastSyncedCommit`、待推送数、冲突数、最近错误（`Typography.Paragraph` 可展开）；按钮 [立即同步] [测试连接] [查看 deploy key]（`Modal` 显示公钥 + 复制按钮 + "到 GitHub 仓库 Settings → Deploy keys 添加并勾选 Allow write access"）[首次导入]（`ImportModal`：是否导入历史、最近 N 个版本）。

## 8. 性能与观感（v1.1，D19）

### 8.1 性能预算（CI 门禁）
| 项 | 预算 | 检查 |
|----|------|------|
| 阅读页首屏 JS（入口 + 静态依赖，gzip） | ≤ 300 KB | `scripts/check-bundle-size.mjs` 读 `dist/.vite/manifest.json` |
| 首屏 CSS（gzip） | ≤ 60 KB | 同上 |
| 编辑页额外加载（Milkdown 等，gzip） | ≤ 600 KB | 同上（单独统计 `editor` chunk） |
| 站内切换页面（已缓存 bundle，内网） | < 300 ms 到内容可见 | Playwright 计时 |
| 首次打开（冷缓存，内网） | < 1.5 s LCP | Lighthouse CI（夜间） |
实现手段：路由级 `React.lazy`、`manualChunks`（vendor-react / vendor-antd / editor）、图标按需引入、重模块动态 `import()`、启动只调 `/bootstrap`、树悬停预取、`keepPreviousData`（10 §4.5）。

### 8.2 观感（对标现网 wiki 阅读体验）
- 浅色头部（白底 + 底部分隔线）、白色侧栏；正文白色卡片，最大宽度 880 px；
- 排版：正文 16 px / 行高 1.75；h1 32 px、h2 24 px（上间距 48 px + 顶部分隔线）、h3 20 px；表格斑马纹、横向滚动；行内代码浅底圆角（参考 dts-rdc `wiki/.vitepress/theme/custom.css` 与 VitePress 默认主题）；
- **不展示内部枚举**：页面类型只用图标表示；同步状态只在非常态时以中文 Tag 显示（同步中 / 冲突），`LOCAL_ONLY`、`SYNCED` 不显示；
- 主操作"编辑"为 primary 按钮，删除等危险操作收进 `⋯` 菜单；
- `token.colorPrimary = '#2f6f5e'`，圆角 6，字体栈 `-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`；暗色模式 `theme.darkAlgorithm`（用户菜单切换，记忆在 localStorage）；
- 可访问性：树支持方向键；图标按钮有 `aria-label`/`Tooltip`；焦点可见；窄屏（< 992 px）侧栏收起为 `Drawer`。
