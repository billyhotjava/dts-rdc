## 目标
在 scratch 目录完整演练一次"copilot 历史重写到 `engine/` 子目录再并入 studio"，确认历史、blame、tag 都正确，并得出可重复执行的脚本。

## 技术设计
- **方案**（ADR-11）：在可丢弃 clone 中执行单次受控历史变换；具体参数由本 Task 的演练脚本产出，目标路径如下，不直接照抄多次 filter-repo 命令。

  | 原路径 | 目标/排除 |
  |---|---|
  | `dts-copilot-ai/` | `engine/engine-ai/` |
  | `dts-copilot-analytics/` | `engine/engine-analytics/`（按 ADR-006 过渡） |
  | `worklog/` | `engine/worklog-history/` |
  | `build.sh`、`dev.sh`、`start.sh`、`smoke-test.sh`、`docker-compose*.yml`、`services/`、`scripts/`、`docker/`、`deploy/` | `engine/deploy/legacy/` 下原路径，仅保留旧部署参考；新的构建入口由 T04 实现 |
  | 其他保留文件 | `engine/` 下同名路径 |
  | `dts-copilot-webapp/`、依赖/日志/工作树产物、已决定排除的密钥路径 | 从导入历史排除；原仓库冻结，webapp 候选模块交 F6/T14 |

  Tag 加 `copilot-` 前缀，分支白名单和来源 refs 写入脚本输入。变换后 fetch 指定 refs 到 studio，在合并分支合入并验证，不强推原仓库。
- **演练检查项**：
  1. `git log --oneline -- engine/engine-ai | wc -l` 接近原仓库 `dts-copilot-ai` 的提交数；
  2. `git blame engine/engine-ai/.../SqlSafetyChecker.java` 显示原作者和原日期；
  3. worklog-history 体积（12 MB，账本#30）是否可以接受；如有大文件（zip，例如 `worklog/prs/v1/*.zip`），评估改用 LFS 或迁到 prs-stack；
  4. 模块目录改名后，`pom.xml` 中的 `<module>` 需要同步修改（记录到 T04）；
  5. 统计 studio 合并后的仓库体积。
- **产出**：`assets/scripts/merge-copilot.sh`（调用同目录 Python 实现）；演练输出、commit map 和 manifest 见 `assets/studio-refactor-20260929.md`。脚本只准备新 clone，不修改源仓库，也不自动合并或推送 studio。

## 演练脚本要求（脚本落地与失败处理）

重写只在可丢弃 clone 中执行，源仓库不改历史。将路径前缀、重命名、排除项整合成经演练的变换，不能假定连续多次 filter-repo 都满足 fresh-clone 检查。明确要合并的分支与重命名 tag，保留源→目标 commit/ref 映射并验证 tag 已导入 studio；仅 fetch 默认分支不算标签验证。旧 webapp 的历史留在冻结来源仓库，目标树不包含 engine/webapp。

脚本失败须停止，不对原工作副本 reset/force。演练使用固定源 SHA，重复性比较文件树及映射，合并提交时间等可变项单列。
