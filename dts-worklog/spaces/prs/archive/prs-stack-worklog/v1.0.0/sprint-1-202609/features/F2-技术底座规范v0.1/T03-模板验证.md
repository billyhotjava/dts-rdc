## 目标和范围
**A. 版本兼容性**（以 `assets/版本基线.md` 为准）：
- 后端：JDK 25 LTS（Temurin 25.0.4）+ Spring Boot 4.1.1 + Spring Modulith 2.1.1 起一个空服务，接入 Flowable 8.0.0、
  Liquibase 5.0.4、PG 18.6 与 JDBC 42.7.13、所选持久层（Boot 管理的 Hibernate，或 MyBatis-Plus 3.5.17）、Valkey 9.1.2、
  SeaweedFS（S3 API）、OTel agent 2.30.0、ShedLock 7.9.0，确认能编译、启动和迁移；
  `kafka-clients` 4.3.1 连通 stack 现有 4.1.2 集群（共享集群升级前的过渡期）。
- 前端：Node 24 LTS + pnpm 11.22 + TypeScript 6.0 + Vite 8.2 + React 19.2 + antd 6.6 + React Router 8.3 的纯 TypeScript 脚手架
  （`strict`、禁用 `allowJs`）能完成构建，`tsc --noEmit` 与 lint 通过；用模板服务的 OpenAPI 生成一次接口类型并在页面中调用，确认类型链路可用；
  核实 pro-components 的正式版本及其与 antd 6 的兼容性（默认不用）。
- 结论：通过 / 部分组件需替换（列清单，替换版本同样按 R-012 规则选定并回写版本基线）。
**B. 多租户 RLS**：在模板中建一张示例表，启用 FORCE RLS，验证：
① 不设 `app.tenant_id` 时查询返回 0 行；② 租户 A 查不到租户 B 的数据；③ 以 A 的身份写入 B 的数据被 `WITH CHECK` 拒绝；
④ 经连接池（PgBouncer 事务模式或 HikariCP）复用连接后，`SET LOCAL` 不串租户；⑤ 应用账号无 BYPASSRLS。
**C. 模板默认能力**：缺少或伪造 `X-DTS-*` 头时拒绝（401/403；OIDC 验签在 Traefik forwardAuth，由 F3 负责，模板不重复实现）；
审计落库；存活/就绪探针分离；outbox 表就绪；Modulith 架构测试能拦住跨模块违规依赖。
排除：业务接口、前端联调。
