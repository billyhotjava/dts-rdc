## 使用场景与验收
调用者：各服务/模块开发者、评审人。触发：新服务或模块开工前必读。
输入：选型结论 + F1 §10 + F6/T01（数据规范章节引用）；结果：底座规范 v0.1 + 服务模板骨架可启动验证通过。
正常流程：T03-A 版本兼容性 spike（与 T01 并行）→ T01 起草 → T02 评审 → T03-B/C RLS 与模板验证 → 发布 v0.1。
替代流程：评审不通过项记修订记录，模板验证失败则回炉 T01，不降标准发布。
失败流程：锁定项（下）到期未决 → 规范标"假设"发布，F3/F4 按假设推进，Sprint-2 前补决议。
锁定项均为技术决策，由架构评审决议，不需要业务确认；涉及口径的约束引用 F1 签字结果。
规则与边界：以下各项必须锁定——BOM/版本（已确认：版本基线 v1.0，按 R-012 选定；待补兼容性验证结论与 Liquibase 许可证结论）、模块边界（Modulith）、多租户数据约束（RLS）、
k8s-ready 部署约束、API/事件/审计规范、PG 子决策、BFF 职责、通知通道、
网关分层（Traefik+forwardAuth，无 Nacos/SCA）、密钥/脱敏（密钥部分依赖 dts-stack sprint-36/37，当前 PLANNING，按假设发布，B-006）、单据打印引擎。其余（ES、k8s 集群运行、服务网格、租户开通控制面）明确延后，不写。
验收示例：Given 规范 v0.1 发布 / When 按模板生成空服务 / Then 本地一键启动，验头、租户隔离（数据库行级安全）、审计默认生效，满足 k8s-ready 清单

## 设计
概念与共享架构：规范是全工程共享基线，维护责任：架构组；引用位置：各服务 README。
概要协作：兼容性 spike → 规范 → 模板（含 RLS 测试基类）→ 空服务 → F4 基线集成。
关键契约：OpenAPI 规范（资源/命令式设计、envelope/分页/幂等/版本；不复刻老 RPC 端点命名，R-004）、
事件信封（CloudEvents）+ 首批事件目录、审计字段、MCP 工具暴露约定（读能力可直接投影，写能力须经 HITL）、
tenant_id + FORCE RLS（fail-closed）、租户级单号、Long 转字符串、绞杀期数据同步与 ODS 暴露约定（R-008）、
k8s-ready 清单（R-011）。
UI 或使用路径：无（后端规范；前端规范拆 React/H5 两节：路由/权限指令/请求封装/SSE 消费，统一 TypeScript 严格模式、接口类型由 OpenAPI 生成；
agent UI 消息协议引用 dts-copilot 契约，不在本规范定义，R-009）。
详细设计：见 T01–T03。
未决项：B-003（租户模型联动 F3/T01；单号方案按 R-010 写入后关闭）；版本基线组合的兼容性（T03-A）；Liquibase FSL 法务意见；B-006（密钥管理依赖 dts-stack sprint-36/37，二者 PLANNING）。
